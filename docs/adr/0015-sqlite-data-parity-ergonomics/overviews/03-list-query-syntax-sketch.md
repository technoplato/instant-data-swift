# Overview 03 — List query: real APIs vs goals (v3 — spell it out)

**Status:** clarification after inventing names that looked “official.”  
Nothing named `Fragment`, `SegmentPreview.combine`, or parent `.select { }`
closure exists in Instant Swift Data today.

## A. What SQLiteData actually does (real code)

File: `upstream/sqlite-data/Examples/Reminders/RemindersLists.swift`

```swift
// REAL — SQLiteData list observation.
// @FetchAll re-runs this SQL-shaped statement when the DB changes.
@FetchAll(
  RemindersList
    .group(by: \.id)
    .order(by: \.position)
    // Join incomplete reminders (for a COUNT), not "load every reminder row into the list model".
    .leftJoin(Reminder.all) { $0.id.eq($1.remindersListID) && !$1.isCompleted }
    // Join CloudKit share metadata (optional).
    .leftJoin(SyncMetadata.all) { $0.syncMetadataID.eq($2.id) }
    // .select builds ONE flat row type for the list — this IS the "map".
    // $0 = RemindersList table, $1 = Reminder table, $2 = SyncMetadata table.
    .select {
      ReminderListState.Columns(
        remindersCount: $1.id.count(),  // aggregate in SQL
        remindersList: $0,              // whole list row
        share: $2.share                 // one field from metadata
      )
    }
)
var remindersLists  // type: [ReminderListState] — NOT [RemindersList] with nested reminders
```

```swift
// REAL — the row type is an app struct, marked @Selection so Columns(…) type-checks.
// This is NOT generated by Instant. SQLiteData/StructuredQueries generate Columns helpers
// for @Selection types.
@Selection
struct ReminderListState: Identifiable {
  var id: RemindersList.ID { remindersList.id }
  var remindersCount: Int
  var remindersList: RemindersList
  @Column(as: CKShare?.SystemFieldsRepresentation.self)
  var share: CKShare?
}
```

**Takeaway:** the list never holds nested “all reminders.” SQL join + `.select`
projects a **flat list row**. Truncation/aggregation happens in that select
(SQL), not in SwiftUI.

## B. What Instant Swift Data actually supports today (real APIs)

### B1. Field `select` — pick attributes, not map to a custom type

```swift
// REAL API today (InstantTypedAPI.swift).
// This only decides WHICH fields are requested from Instant.
// It does NOT run a Swift closure. It does NOT build RecordingListRow.
// Return type of the query is still about Entity / snapshots — not your list DTO.

Recording.query
  .select(Recording.title, Recording.durationSeconds)
// → still "query for Recording", just fewer attributes on the wire/cache plan
```

### B2. `include` — load related entities (with a hard limit today)

```swift
// REAL API today.
// Forward include: follow a ref field to another entity type.
Recording.query
  .include(Recording.owner)  // example shape; exact relation names are app schema

// Reverse include: children that point at this entity (e.g. segments → recording).
// Second argument can narrow the child query (filters, order, field select)…
Recording.query
  .include(Recording.segments, Segment.query.order(Segment.startTimeSeconds, .descending))
```

```swift
// REAL constraint today (InstantTypedAPI.including):
// Nested limit / offset / first / last / cursors on the INCLUDE query are FORBIDDEN.
// precondition: "InstantEntityQuery.include does not support nested pagination."
//
// So this DOES NOT WORK today:
//
//   .include(Recording.segments, Segment.query.limit(2))  // traps / rejected
//
// That is library work we still need (ADR 0015 Q28), not something you can call.
```

### B3. `@FetchAll` on one entity query

```swift
// REAL pattern used in library examples (VoiceTrail-style).
@FetchAll(
  Recording.query
    .order(Recording.updatedAtMs, .descending)
    .limit(50)
)
var recordings: [Recording]
// You get [Recording]. Includes (if any) hydrate related entities on those models
// when the decode/include pipeline supports it — still not a custom list DTO.
```

### B4. `InstantFetchRequest` — multi-query zip + **your** transform

```swift
// REAL API today (InstantSwiftData.swift InstantFetchRequest).
// This is the only "map in the request" that exists officially:
// you pass 1..N entity queries and a Swift transform.

struct ExampleRequest: InstantFetchKeyRequest {
  var fetchRequest: InstantFetchRequest<[String]> {
    InstantFetchRequest(
      Recording.query.limit(50),
      Segment.query  // WARNING: this is a GLOBAL segment query, not "per recording limit 2"
    ) { recordings, segments in
      // This closure is YOURS. Not library-generated.
      // Easy to misuse (join in memory across everything) — ADR 0001 hates that
      // for unbounded merges. Still: this is what exists.
      recordings.map(\.title)
    }
  }
}

@Fetch(ExampleRequest())
var titles: [String]
```

**Takeaway:** Instant today has **no** SQLiteData-style  
`.select { MyRow.Columns(...) }` on a joined graph.  
It has: entity queries, field select, include (no nested page/limit), and
FetchRequest transforms you write yourself.

## C. What we want for the list (goal — not shipped)

You asked for:

1. List shows summary + activity + **up to two most recent segments**
2. UI shows **two lines of text** even if segment text is huge
3. **Map** in the **query/request**, not in the view (prefer name map over project)
4. Correct relational design, not denorm full preview text
5. Type-safe so you are not digging random nested graphs in the view

That needs **library work**. Below is a **goal sketch** with every invented
name labeled `// GOAL — not in library yet`.

## D. Glossary (names I invented earlier — discard as Instant API)

| Name I used | What it actually was |
| --- | --- |
| `SegmentListFragment` | Made-up DTO. Not Instant. You can use any struct or just `Segment`. |
| `SegmentPreview.combine` | Made-up helper. Just a function that builds `[String]` lines. |
| `RecordingListRow.Columns` | SQLiteData `@Selection` pattern — Instant does not have this yet. |
| `fragments` | My nickname for “≤2 segment rows for this recording.” Not a library type. |
| Parent `.map { recording, segments in }` | **Goal** spelling (user: map not project). Instant `.select` today only takes attribute paths. |

## E. Direct answers

**Do I need a segmentless fragment?**  
No. That was optional. You can project from full `Segment` if the query only
returns two of them. Fragment was only “don’t carry wordsJSON on the list path.”

**Is fragment / Columns official Instant?**  
No.

**What is Reminders doing?**  
SQL join + `.select` into `@Selection` row type so `@FetchAll` is already
`[ReminderListState]`.

**Where does truncation run in the goal world?**  
In the **request projection** (like SQLiteData’s select), producing
`previewLines: [String]`. Not in `View.body`. Not on Instant’s server.

**Can we do limit-2 segments per recording today?**  
**No.** Include forbids nested pagination. That is the library gap.

## Naming (decided with user)

- Fetch-time transform name: **map** (not project).
- Empty child include → `[]`; map supplies safe empty preview.
- Nested include limit is library work (precondition forbids it today).
