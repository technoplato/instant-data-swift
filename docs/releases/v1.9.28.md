## Release focus

A live write fingerprints its optimistic effect once per step instead of twice (#1007).

1. **A save and an acknowledgement fingerprint a write once each** (red `a56c9786`, green `73e3ff7c`). The
   optimistic-effect receipt fingerprint encodes a write's transaction and rollback with `JSONEncoder` and hashes the
   text; a Time Profiler trace of the write harness put 5.9% of all CPU in it. The save computed one only to ask
   whether the write had one, before computing the one it stores; `PendingMutation.hasOptimisticEffectReceiptFingerprint`
   makes the same checks without encoding anything. The acknowledgement computed it for its receipt check and again for
   its claim check; it now computes it once for both. The lifecycle resolution, the explicit flush, the delivery
   metadata save and the terminal lifecycle record take server acceptance from the receipt check they have just made,
   since an acceptance counts only over a prepared receipt.

## What stays the same

Every check compares the same fingerprint with the same stored receipt; only how many times it is computed changes.
The claim keeps its order: its acceptance check fingerprints only rows the server accepted, and it skips rows that do
not need delivery before it fingerprints them.
