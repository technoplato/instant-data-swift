commit is `2f3d735a`. It carries 1.9.29 (#1035).

## Release focus

Progressive media, first released in 1.9.26 (`0fe995b2`, #1012, ADR 0021), gets two fixes before an app turns it on.

- **A stream row's `updatedAtMs` never moves back** (red `c5da394b`, green `2f3d735a`). The writer stamps each stream
  row with the later of the clock and the last stamp it wrote, which the spool keeps across a relaunch. Before, a device
  clock that stepped back stamped an earlier time, and a schema whose rules refuse an update time that moves back (the
  consuming app's generated rules do) would have refused the stream row and, with it, the segment row in the same
  transaction: that segment would never have been listed for players.
- **The resource loader's request box says what protects it** (`0f1d2ebc`). 1.9.26 added one production
  `@unchecked Sendable` without the `SAFETY:` comment `SwiftConcurrencyGuidanceTests` requires, so that test failed on
  main from 1.9.26 to 1.9.29.

What progressive media is (since 1.9.26): `InstantProgressiveMediaWriter` appends compressed segments on the device and
delivers them, each `$files` file before its rows, oldest first, with no attempt while the network path is down and a
1-60 s backoff that resets only after a success; `InstantProgressiveMediaReader` lists the rows and reads URLs a page at
a time; `InstantProgressiveMediaPlaylist` is the HLS media playlist; the `InstantSwiftDataMedia` product holds
`InstantAudioSegmenter` (AVAssetWriter's HLS segmenter: AAC-LC, 24 kHz, 32 kbps, 6 s fragmented MP4 segments) and
`InstantProgressiveMediaResourceLoader` (AVPlayer's playlist from the rows, and a redirect to each file). ADR 0021 holds
the measurements: 23.7 times smaller than 48 kHz 16-bit PCM, wideband PESQ 4.32 / 4.11 / 4.28 on three real
recordings, AVPlayer 37.5-41.7 s behind a growing playlist with no stall.

## What stays the same

No schema, migration or public API change. `InstantProgressiveMediaSpool`'s record gains one optional field; a spool
written by 1.9.26-1.9.29 reads as before and starts its stamps from the stream's `createdAtMs`.

## Checks

- **Red, then green** (Mac mini M4, Xcode 27 beta, debug): `aClockThatStepsBackNeverStampsARowEarlier`, each read of the
  clock a second earlier than the last: on `c5da394b` the stamps fell below the stream's `createdAtMs` (2 issues); on
  `2f3d735a` the progressive media suites and `SwiftConcurrencyGuidanceTests`, 31 tests in 6 suites, pass.
- **Platforms** (Mac mini, on `0f1d2ebc`, before the stamp change, which is platform-neutral Swift): `InstantSwiftDataMedia`
  with `InstantSwiftData` builds for iOS (arm64) and watchOS (arm64, arm64_32). The generic watchOS destination's
  armv7k and swift-crypto's watchOS 8.0 target fail before any library code, so that build sets
  `ARCHS="arm64_32 arm64" WATCHOS_DEPLOYMENT_TARGET=9.0`, the package's minimum.
- **The whole bundle**: not run again for this release. On 1.9.28, idle on the Mac mini, it failed 1 of 1,401 tests,
  the `SAFETY:` check `0f1d2ebc` fixes (library-red-1021, on #1012); the laptop's run under load 236-520 failed 66 of
  1,392, 56 of them listed in `Tests/known-failing.txt` and 9 more timing tests under that load.

## Not changed here

- The iPhone's encoding CPU is not measured yet (its developer disk image was not mounted); ADR 0021 carries the Mac's
  figure, 0.08 CPU seconds a minute of audio for AAC-LC at 24 kHz.
- A Watch plays progressive media only from an http(s) playlist or by decoding segments itself: watchOS has no
  `AVAssetResourceLoader`, and AVPlayer does not play a `file://` playlist.
