# Instant Swift Data 1.9.62

Status: published under the maintainer's standing authorization for fixes, typed on 2026-10-15: "Fix things when
they're broken. Don't ask me permission." A release branch off `v1.9.61` (`fb930584`) with the source and test diff
of one merge on `main` applied: #1494 (`c17bf998`). It carries 1.9.61.

## Before you upgrade

No public API change, no conversion and no storage change. 1.9.61 opens a store this version has opened.

## Release focus

**A server frame plans in two persistence turns after its seed, and a retried apply names where it went stale**
(#1494; part 1 red `b27bca3f`, green `4f2e76e9`; stale stages red `47f0573b`, green `3f04436d`; turns red `670758fa`,
green `5922e9af`; merge `c17bf998`).

- A step's reads share one turn on the store's queue, so a server frame's apply waits behind other work fewer times.
- `server-apply.operation-gate-held` gains `staleStages`: when an apply is retried, the log says which stage saw the
  change that made it stale.

Measured on a Mac mini (release), one interleaved job on the recording exercise:

| Measure | Before | After |
| --- | --- | --- |
| persistence turns, 50-row server refresh | 12 | 6 |
| persistence turns, over a pending write held as a body | 13 | 8 |
| live-session entries a frame | 4 | 2 |
| library CPU, whole exercise | 16,611 ms | 16,615 ms |
| apply attempts a frame | 1.116 | 1.159 |

Fewer turns did not buy CPU or write latency; both are unchanged within the run. Attempts a frame rose slightly; their
stale sources are #1524.

## Not in this release

  Mac mini (release, cross-SDK runtime benchmark), it adds 0.26 ms to a tight-loop transact (0.449 -> 0.712 ms p50,
  +58%), and its owner has not marked it ready for a build, so this release branches from `v1.9.61`, not `main`. With
  it left out, this branch's `Sources` and `Tests` equal `main` at `c17bf998`.
- The merge's change-log, PROGRESS, plan and ADR edits stay on `main`.
