# Instant Swift Data 1.9.41

Status: published under the maintainer's standing authorization for fixes, typed on 2026-10-15: "Fix things when
they're broken. Don't ask me permission." and the instruction of 2026-10-23 to land every green step on main. The
release is cut at main `ec1257ba`; its last code commit is `99318502`. It carries 1.9.40.

## Before you upgrade: there is no going back

1.9.40 already made a store it opened unwritable by any older build (migration 0032, #1121; see its release document).
1.9.41 adds one more such change: every open rebuilds the outbox's three rare-state indexes as partial indexes (#1115,
second slice), and fix-storage-1076 reports that an older build's `INDEXED BY` queries cannot use them, so a 1.9.40
build cannot deliver from a store 1.9.41 opened either. That is from the code and the index definitions, not reproduced
on a device. An app that keeps its store across installs (the consuming app does) must delete its data before an older
build is installed over 1.9.41.

## Release focus

Reads and holders stop waiting for gate work they do not need, and the launch and the store's reads allocate about
half as much. Each fix is a red commit, then a green one:

1. **A connection status, a status observation and a session observation answer without the operation gate**
   (#1132; red `21730c33`, green `de2388ec`). They answer from the latest status and session the writers computed under
   the gate, and a new observer gets the latest value in the same registry turn as any publish, so it can neither miss
   one nor register late. Bootstrap seeds them. A session observation started during a sign-in sees the session as it
   is, then the sign-in when it commits, as upstream `subscribeAuth` calls back with the cached user at once (`340319ef`
   updates the three tests that expected the old waits).
2. **A hydration's re-check waits only for a holder that may be writing what it read** (#1133; red `9005cc07`, green
   `99318502`). A caller names what it writes as it takes the operation gate (`writes:`, set as the gate hands it over),
   and the holders that write no store facts name none: the server apply's snapshot, plan and catch-up, the
   acknowledgement, a registration, the local reads, the retry window, an upload's record, the VACUUM, the delivery
   claim and the status reads. A prune batch names the entities it releases. Adopting another connection's SQLite
   writes still reads as writing anything.
3. **A large closed result is released a bounded chunk at a time** (#1129, third slice; red `a565f0b7`, green
   `68d37d42`): its row is re-keyed out of its key's way and keeps its ownership rows, so its batch no longer deletes
   every ownership row in one cascade; a crash leaves the released row for the next prune or open.
4. **A prune batch holds the server-apply gate too** (#1129, fourth slice; red `1d09aac1`, green `9581503d`), at
   background priority, so no batch commits inside a frame's apply and makes it plan again.
5. **A prune batch checks 1,000 facts, not 5,000** (#1129, `6590a7e4`).
6. **Reads take the store's attribute index and read facts from their columns** (#1150, #1111; reds `1256f9e0`,
   `713a5f9d`, refactor `6fdf9ff2`, greens `a641f2ea`, `e7dacb2d`).
7. **The store's deferred loads read facts from their columns** (#1147, step 5; red `9a6929a4`, green `ffbd3e87`).
8. **A sharded set keeps one plain set until it holds more than 32 elements** (#1146, step 1; red `9e300d59`, green
   `af0f729e`).
9. **The launch reads its resident facts from their columns, one id string per entity and attribute** (#1149 step 1,
   #1146 step 2; red `a48fe943`, green `4c190959`).
10. **A live write writes none of the outbox's rare-state indexes** (#1115, second slice; red `84a6195b`, green
    `12f487e1`): the three indexes are partial on the states they find.

Test commits with them: `743640fd` (#1131's observer-send test acknowledges its write), `375beb42` (#1119's guards: an
echo with a write pending, and a backlog's first echo, write no temporary file), `f834c614` (#1111's local read meets
its real-size budget) and `ec1257ba` (two allocation bounds hold in optimized builds, where they were measured).

## What stays the same

No public API change. `AsyncSerialGate.enter` and `enterUnlessCancelled` take an optional `writes:` (internal; the
default still means "may write anything"). The prune unloads and drops the same results and facts, a
status read answers what a read under the gate would (a test holds it to that after a connection, a write, its
acknowledgement, a refusal and a close), and a hydration still never pairs an emission with a write saved during its
read.
