# Instant Swift Data 1.6.0

Status: release document. `v1.6.0` is published only after the gate below passes on the release commit: through `.github/workflows/release-gate.yml` when the home runner is online, otherwise by direct maintainer authorization with the same gate run locally and its results recorded in the tag message and the GitHub release (the `v1.5.7` precedent).

## Release focus

Writes cost what they touch, not what the entity holds.

Before this release, a write to one fact of an entity handled every fact of that entity three times: it copied them for rollback, materialized and sorted them as the "changed" set, and SQLite read back and rewrote all of them. Entities that accumulate facts therefore got slower to write the longer they lived. Scribe is the sharpest case: every transcript segment adds one `recordings/segments` link fact to its recording, so after 30 minutes each new segment re-copied, re-sorted, and re-persisted about a thousand links.

Separately, every local `transact` built a snapshot of the entire store for shared-root authorization, even in apps with no shares.

## What changed

1. **Per-fact write scope.** Preparing a mutation now records which facts each entity touched (`InstantFactScope`: named attributes, or individual values of multi-value attributes). Rollback capture, the changed-fact set, and SQLite persistence use only those facts. Server apply and failure removal, which compose several prepared mutations into one commit, union their scopes.
2. **Safe widening.** Deletes widen to whole entities only where the cascade actually removes entities. A rollback may delete an entity outright only when the write provably created it, and entities changed without a recorded scope fall back to whole-entity handling.
3. **In-place multi-value slots.** Adding one value to a large multi-value attribute no longer copies the attribute's existing values (copy-on-write was triggered on every insert).
4. **No store snapshot without shares.** Shared-root write authorization runs only when the app has an unrevoked share (`SQLitePersistenceStore.hasActiveShares(appID:)`, an `EXISTS` query). Apps with shares get the same authorization as before.
5. **Documentation: nested limits.** The Instant server paginates only the top level of a query (`instaql.clj`, `page-info-of-form`). A nested `limit` inside an include trims results on the device after the full child set has downloaded. The TypeScript client does the same and warns about it. The docs used to imply otherwise. For lists that refresh on every write, bound child data on the server, for example with has-one links. ADR 0015 Q32 and Q33 record both decisions.

Why upstream has no equivalent: the TypeScript `Reactor` keeps pending mutations separate and layers them over server data on every read, so it never captures rollback state. This library keeps one persisted store and peels optimistic overlays off before applying server results, so it has to capture them. After this release it captures only what each write touched.

## For users of the library

- **API:** one additive public method, `SQLitePersistenceStore.hasActiveShares(appID:)`. The rest of the new surface is `package`-internal. No source changes are required.
- **Storage:** no SQLite schema change or migration. Existing stores open as they are.
- **Behavior:** unchanged apart from speed. Rollback, rejection isolation, cascade deletes, schema reconciliation, and shared-root authorization keep their tests and semantics.

## Measured

Deterministic, Debug build, Apple M1 Max:

| Workload | 1.5.7 | 1.6.0 |
| --- | --- | --- |
| 50 prepared writes, recording with 16,000 links | 33.4 s | 0.13 s |
| 500 link inserts into a 16,000-link slot | 0.27 s | 0.019 s |
| 40 one-field writes, 20,000-fact store, no shares | 6.09 s | 0.069 s |

The three tests in `InstantEntityWriteScopeTests` guard these costs with absolute bounds.

Scribe, 30-minute recording on a Mac, same transcript volume (1,011–1,012 sections). The two arms also differ in the app's list query (the right-hand arm uses Scribe's new bounded preview slots), so read this as the combined result:

| | 1.5.7, list previews off | 1.6.0 candidate `636c3488` + preview slots |
| --- | --- | --- |
| Memory, minutes 5–10 → 25–30 | 124 → 146 MB | 117 → 123 MB |
| CPU, same windows | 26% → 39% | 27–29% → 31–35% |
| Peak footprint | 157 MB | 131–137 MB |
| `ScribeRecordingLibrary.persist` at minute 25, per 30 s | 2.88 s | 1.15 s |

`TripleIndexes.materializedTriples` no longer appears in the profile. The soak predates the snapshot gate (item 4), which removed about another 0.9 s per 30 s at minute 25.

## Known remaining costs

- Preparing a transaction on an isolated copy of the hot store still copies each large map the write mutates, once per transaction. That covers the link slot, its value index, and the reverse-link index. This cost is linear in the size of the largest mutated attribute, not in the size of the entity or the store.
- Persisted live-query results are sorted on every update (about 0.6 s per 30 s at minute 25 of the Scribe soak).

## Correctness contract

- Local writes complete after local materialization and durable outbox persistence, never after an implicit cloud wait.
- Offline writes survive relaunch, drain in order, and preserve newer optimistic state during server refresh.
- Rejection is isolated per mutation, query, stream, and media item. Rolling back a rejected write restores exactly the facts it touched.
- Rapid open-segment rewrites remain monotonic through finalization.
- Swift→TypeScript and TypeScript→Swift lanes must report zero lost, duplicate, reordered, or finalized-regression updates.
- Linked and infinite-query fixtures must preserve bounded result cardinality and deterministic result counts.
- Entity delivery and progressive audio/media transfer remain independent.

## Performance contract

Run:

```bash
validation/run-performance-gate.sh deterministic
validation/run-performance-gate.sh live
```

Default policy requires:

- Swift p50 and p95 latency no slower than the pinned TypeScript core.
- Swift throughput at least equal to TypeScript for equivalent work.
- Scribe-shaped physical-footprint and retained-query memory tests to pass.
- Durable enqueue, offline restore, and reconnect drain to meet the same ratio policy.
- Compiler and runtime warnings to remain at zero.
- Every correctness and performance comparison to emit zero failures.
