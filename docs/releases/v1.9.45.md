# Instant Swift Data 1.9.45

Status: published under the maintainer's standing authorization for fixes, typed on 2026-10-15: "Fix things when
they're broken. Don't ask me permission." and the instruction of 2026-10-23 to land every green step on main. The
release is cut at main `9936ffe4` (its only code commit since 1.9.44). It carries 1.9.44.

## Before you upgrade

Nothing new: 1.9.45 adds no migration and changes no stored format. 1.9.41's warning stands: a store 1.9.40 or later
opened cannot be used by an older build, so an app that keeps its store across installs must delete its data before an
older build is installed over it.

## Release focus

**The wire meter says which query each answer's bytes carried** (#1117; red `14aee4fb`, green `f52532b2`, landed again
as `9936ffe4` after 1.9.44). `InstantWireMeter` (#1124) counted the live socket's frames and bytes by op only. On
one device a recording received about 1.15 MB of `refresh-ok` text per final line, and only two copies of the device's
store told which live queries carried it. A `refresh-ok`'s computations each carry their `instaql-query`, so the
library now counts each computation's bytes under its query's shape, and a query's first answer (`add-query-ok`,
`add-query-exists`) with its whole frame:

- The frame parser keeps the byte length of each element of a frame's top-level `computations` array as it passes it
  (no second pass, no copy).
- A shape names the query's namespaces, each with its page size (`limit`, `first` or `last`) and the attributes its
  `where` tests, never a value it compares: `transcriptionSegments/16[recordingID]`,
  `recordings[deletedAtMs,id]`. At most 48 shapes are kept apart; a later one counts as `other`.
- `InstantWireSnapshot.receivedByQuery` holds them and subtracts like the ops; the minute's `network.wire-summary`
  names the three heaviest (`query.1` to `query.3`, `shape=frames/bytes`).

## What stays the same

The frames are unchanged; this only reads them (upstream's server sends each changed query whole, `session.clj`
`handle-refresh`). A frame `JSONDecoder` reads (the parser declined it) counts under its op only. The socket's own meter
(`InstantURLSessionLiveWebSocket(url:wireMeter:)`, a test's) still counts ops; the per-query counts go to the process's
meter, where the frame decoder runs. Decoding stays under its bar: 0.313 of `JSONDecoder`'s thread CPU on a 94,776-byte
refresh (bar 0.33; 0.299 on the release tree).
