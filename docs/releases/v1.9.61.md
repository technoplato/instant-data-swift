Status: published under the maintainer's standing authorization for fixes, typed on 2026-10-15: "Fix things when
they're broken. Don't ask me permission." A release branch off `v1.9.60` (`a00c1618`) with the source and test diffs

## Before you upgrade

No public API change, no conversion and no storage change. 1.9.60 opens a store this version has opened.

## Release focus

**Every store connection keeps SQLite's temporary structures in memory** (#1504; red `6ec56cba`, green `a92b8ca4`,
merge `3374ba97`).

- The writer sets `temp_store` to memory at the end of its bootstrap and on reopen; every read connection sets it at
  open. SQLite's sorter and temporary b-trees no longer go to a file.
- Before: the device's energy ledger counted 34,124-36,677 `sqlite.temp` writes an hour of recording (19-49 MB an
  hour), and 470,007 (166 MB an hour) across one evening's eight launches. Expected after: 0.

**An acknowledgement reuses the kept receipt fingerprint; a frame is sent by one task** (#1497, #1496; red `13699326`,
green `a55a0912`, inputs key `ca5c830e`; red `af675e6b`, bench `7d024be3`, writer `0a7a9595`, `4bd0f806`, `66d372e8`,
`40e83b28`; merge `b60a2c09`).

Measured on a Mac mini (release), the recording exercise against `main` `62c16ebf`, interleaved in one job, 2 rounds
alone and 2 beside six busy loops; the send path against `7d024be3`, 3 runs each:

| Measure | Before | After |
| --- | --- | --- |
| acknowledgement CPU a call, alone | 834 us | 506 us |
| acknowledgement CPU a call, loaded | 613 us | 419 us |
| save + claim + acknowledgement, loaded | 4,624 us | 4,384 us |
| CPU per send | 24.58 us | 20.69 us |
| tasks per send | 3 | 1 |

`localSave` rose 1,733 -> 1,914 us loaded (+10%, the receipt key's hash); #1523 carries the rest.
