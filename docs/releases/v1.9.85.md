## Before you upgrade

No public API change on iOS, iPadOS, macOS, visionOS or watchOS, no storage schema change, no behaviour change there.
On tvOS the library now compiles; `BrowserOAuthAuthorizer` is not part of the tvOS build.

## Release focus

**The library compiles for tvOS** (#2287; red and green below, merge on `main`).

- Why: a consuming app's first tvOS build failed in `InstantAuthProvider.swift`. The gate on the browser and Apple ID
  authorizers excluded watchOS but admitted tvOS, which has AuthenticationServices and UIKit but no web authentication
  presentation: `ASWebAuthenticationPresentationContextProviding`, `presentationContextProvider`,
  `prefersEphemeralWebBrowserSession` and `ASWebAuthenticationSession.cancel()` are unavailable there. Separately,
  `ASAuthorizationController.cancel()` is tvOS 18.0 and later while its availability check said tvOS 16.
- Now: on tvOS `BrowserOAuthAuthorizer` leaves the build, and an authorization-code provider throws "Browser
  authentication is unavailable on this platform" there, as on watchOS. `AppleIDAuthorizer` (Sign in with Apple) stays
  on tvOS, and its cancel runs from tvOS 18.
