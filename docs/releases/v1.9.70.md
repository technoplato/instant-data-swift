## Release focus

**The acknowledgement and the server apply find a write's receipt by its stored bytes again** (#1523; `37790b67`, the
lane's `6ff60ee9` on `main`).

- 1.9.69 keeps each write's receipt fingerprint by the SHA-256 of the body bytes its save binds. The server apply's
  body pages and staging still looked it up by the write's inputs, which the save no longer keys it by, so every
  pending write an echo replayed was fingerprinted again, and a body the echo changed was kept without its bytes, so
  that write's acknowledgement fingerprinted it once more: the acknowledgement cost about 190 us more a call than in
  1.9.67.
- Now the body pages pass the bytes their row stores, the staging keys the fingerprint by the bytes it stages (and
  compresses them once, for the key and the bind), the supersession tail's check uses its row's bytes, and a
  supersession's lifecycle record takes the fingerprint its save just computed. Each check compares the same
  fingerprint with the same stored column as before.
