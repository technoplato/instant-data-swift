# Instant Swift Data 1.9.57

Status: published under the maintainer's standing authorization for fixes, typed on 2026-10-15: "Fix things when
they're broken. Don't ask me permission." Cut from `main` after three performance fixes from the #1482 concurrency
audit landed (#1491, #1492, #1498). It carries 1.9.56.

## Before you upgrade

No public API change and no conversion. `instant_query_cache` gains four nullable columns at the first open
(`answer_digest`, `store_revision`, `attribute_revision`, `emission_sequence`; #1498). A row written before them is
read from its JSON alone and written whole at its next read. 1.9.56 opens a store this version has opened: it names
its columns and leaves the new ones alone. A rollback past 1.9.56 still needs its store reset (1.9.56's own note).

## Release focus

**Less work per write, per send and per one-shot read**, each fixed at its source; no write is delayed, batched or
dropped.

- **A new local write encodes its body once** (#1491; red `efc0656f`, green `02b7cf8a`, merge `1e1ba548`). The 8 MiB
  body bound reads the stored body's bytes instead of encoding the body a second time: 10 writes make 10 sorted-key
  encodes, where they made 20.
- **One attribute resolver per server schema, kept across sends** (#1492; red `8b5a4584`, green `14ee7622`, merge
  `4ba76de7`). The wire encoder built an index of every attribute in the schema for each mutation it sent; it now
  builds it once per schema the server states and reuses it.
- **A one-shot read writes its answer to the query cache only when it changed** (#1498; red `38c426f6`, green
  `2c1c003d`, merge `c9dc143d`). A cache row holds its answer's SHA-256 digest, computed on the reader's task. An
  unchanged answer updates the row's time, revisions and sequence in one statement and encodes nothing; a first or
  changed one is encoded on the reader's task, never on the persistence actor, and written whole. A fresh store's
  first answer takes one more persistence turn (the relaunch pin moves 14 -> 15; ADR 0018's log). No read answers
  from `instant_query_cache`; `cachedQuery(_:)` and `cachedQueries()` return what they did.
