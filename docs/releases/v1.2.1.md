## 1.2.1 — watchOS compiles again

1.2.0 shipped the native Apple Sign-In and browser OAuth authorizers. It also
broke every consumer that builds for watchOS, which includes any iOS app
embedding a watch companion. If you are on 1.2.0 and build for watchOS, upgrade;
there is nothing else in this release.

This surfaced while building Scribe for a physical iPhone. Scribe's iOS app
embeds `ScribeSharedWatch`, so an iPhone build compiles the watchOS slice too.
The build failed with 216 failures, and every root error came from one file.

### What was wrong

The authorizers were gated on:

```swift
#if canImport(AuthenticationServices) && canImport(CryptoKit)
    && (canImport(AppKit) || canImport(UIKit))
```

`canImport` answers whether a module exists, not whether the API you want exists
inside it. watchOS ships a UIKit module, so the guard passed — and then the body
referenced `ASPresentationAnchor`, `UIApplication.connectedScenes`,
`UIWindowScene`, `ASWebAuthenticationPresentationContextProviding` and
`ASAuthorizationControllerPresentationContextProviding`, none of which exist on
watchOS. Thirteen unavailability errors, on a platform the package explicitly
declares as supported via `.watchOS(.v8)`.

### What changed

The three guards now also require `!os(watchOS)`. No new code path was added:
watchOS falls through to the `#else` branch that was already there, which throws
an `InstantError` reading "Browser authentication is unavailable on this
platform" or "Native Sign in with Apple is unavailable on this platform". That
is the correct behavior — watchOS cannot present either flow — and it is now a
clear runtime error instead of a compile failure.

Deliberately not changed: tvOS and macCatalyst guards are untouched. Only
watchOS produced errors, and widening the exclusion on speculation would remove
working platforms.

### How this was verified

Both directions, on the same command. With the fix reverted,
`xcodebuild -scheme InstantSwiftData -destination 'generic/platform=watchOS'`
fails with the same thirteen errors seen in the Scribe build. With the fix
applied, `** BUILD SUCCEEDED **`.

For blast radius: the change touches the file that owns all provider
authorization, so `swift test --filter Auth` was run and passes 71 tests across
15 suites. The eight-suite coupled acknowledgement selector from 1.2.0 still
passes 139 tests with five asserted known diagnostics.

Note that on macOS — where the test suite runs — `!os(watchOS)` is true, so no
test observes a behavior change. The compile check is the proof here, which is
why it was run in both directions rather than asserted.

Still unproven, unchanged from 1.2.0: tracker issue #117's two criteria remain
unsatisfied, and there is no installed-watchOS acceptance evidence — this
release proves the watch slice compiles, not that auth behaves correctly on a
physical Apple Watch.

### Upgrading

Bump the pin to `1.2.1`. No source changes required. If you do not build for
watchOS, 1.2.0 and 1.2.1 are behaviorally identical.
