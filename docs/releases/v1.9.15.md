# Instant Swift Data 1.9.15

Status: published under the maintainer's standing authorization for fixes, typed on 2026-10-15: "Fix things when
they're broken. Don't ask me permission." and the instruction of 2026-10-23 to land every green step on main. The
checks that ran are below; the last code commit is `4512739a`. It carries 1.9.14 (#959).

## Release focus

A write's steady cycle (save, claim, acknowledgement, the server's echo) rewrites fewer unchanged rows (#1007).

On a device, one write's cycle rewrote about 68 whole 4 KB pages of the store's write-ahead log in four transactions,
most of them bookkeeping that did not change. Two of those rewrites change no row's content:

1. **A metadata row is written in place.** Revision bumps, saved metadata values and deferred-result markers used
   `INSERT OR REPLACE`, which deletes the row and inserts it again under a new rowid, so every bump rewrote the table's
   leaf and its key index, in every transaction. They now use `INSERT ... ON CONFLICT(key) DO UPDATE`.
2. **An acknowledgement leaves a write's unchanged key rows alone.** It saved the write again with the same keys, and
   `replaceOutboxWriteKeysWithoutTransaction` deleted the write's key rows and inserted the same rows again, on new pages
   of three b-trees. It now reads the stored keys first and returns when they equal the new set (the rows are the keys).

## What stays the same

No public API, schema or migration change. Every metadata row and every write-key row holds exactly what it held before;
only their rowids stop moving. Delivery, acknowledgements, server applies and the outbox's order are unchanged.

## Checks

- **Red, then green.** `InstantOutboxPageChurnTests` (red `63aff39b`, green `4512739a`): on 1.9.13 an acknowledgement in
  the fast-drain fixture moved its write's 11 key rows to new rowids and a revision row to a new rowid, and wrote 19
  SQLite pages; with the fix both tests pass and the acknowledgement writes 9 pages.
- **The whole suite on the same machine** (a Mac mini, Xcode 27 beta, InstantSwiftDataCoreTests built alone): 144
  failing tests on this tree, against 145 on 1.9.13's tree; the tests that differ pass alone. (One earlier run failed 16
  more with "unable to open database file" while another session's library tests shared the machine; its rerun had none.)
- **Measured: the write harness** (release, a Mac mini, load 2-4; 300 writes of a recorded session with 40 bystander
  observers, three interleaved rounds each against 1.9.13): logical writes 417-420 -> 391-392 KB per write (-6%); the full
  write lifecycle (save, send, acknowledgement, the echo, the prune) 386-387 -> 360-361 KB per write (-7%); CPU unchanged.
- **Not yet:** a device check; the consuming app's ledger should show `logicalWriteBytes` per Instant write down by about
  that much while the outbox is empty.

## Not changed here

- The outbox's insert, claim, acknowledgement and delete still touch eight index leaves each; fewer always-on indexes
  would save more (#653 item 6).
- A server apply during a backlog still copies every pending body into file-backed temporary tables (#1007).
