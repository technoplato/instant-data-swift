## Before you upgrade

No public API change and no conversion. One storage addition: opening a store creates
`instant_outbox_creation_order_idx` on `instant_outbox (created_at_ms, mutation_id)` when it is missing. 1.9.62 opens a
store this version has opened; SQLite keeps the extra index and maintains it.

## Release focus

**The outbox tail is the last entry of a creation-order index, not a sort of every row** (#1491 amendment 3; red
`e10668ae`, green `e712d3e3`, guard `bf8748e0` and `7a67778d`; merge `15629f06`).

- Every local write reads the outbox's newest row inside the operation gate, and every server apply's plan reads it
  twice. Without an index in that order, SQLite scanned the whole outbox and sorted it on each read.

Measured:

| Measure | Before | After |
| --- | --- | --- |
| tail read, 700 outbox rows (laptop) | 291 us | 29 us |
| tail read, 5,400 offline rows (laptop) | 2.25 ms | one index entry |
| recording exercise, steady transact hold p50 beside load (Mac mini, release) | 2.70 ms | 2.60 ms |
| server apply plan hold (same job) | 1.35 ms | 1.04 ms |
| server apply plan CPU a call, alone (same job) | 852 us | 807 us |
| outbox log frames a write | 23.0 | 25.0 |

The cost: a save and an echo each write one page of the new index, so #1115's frame budget moves from 24 to 25.
