## 1.5.3 — Live apply isolation + Scribe-shaped memory soak gate

Two follow-ups after the **1.5.1** infinite short-page Jetsam fix and **1.5.2**
instrumentation.

### Live apply no longer dies on legacy failed outbox rows

A failed mutation written before durable optimistic-overlay metadata
(`optimisticOverlayState` / rollback) still blocked every
`applyServerTransaction` on live `add-query-ok` / `refresh-ok`. That produced
`connection.receive-loop-failed` / `persistenceFailed` reconnect thrash
(recipes-v3 mutation `773e50f4-…`, Scribe indefinite loading).

**1.5.3** isolates **failed** pre-overlay rows during server apply (diagnostic
`outbox.mutation.legacy-unknown-isolated`) and continues applying server truth.
Retry/discard still refuse without guessing local cache effect (#134).

### Publish gate: Scribe-shaped linked-infinite memory soak

`LinkedInfiniteScribeShapedMemorySoakTests` seeds a production-order
recordings → transcriptions → words graph (page size 50) and fails when
physical footprint growth exceeds the documented budget. Invoked from
`validation/verify-scribe-shaped-memory-soak.sh` and `verify-v1-release.sh`
(#150). Gate on **footprint**, never VSZ.
