## Release focus

**The transaction-id interner every copy of the store's indexes shares no longer races** (#1141; red `c8277988`,
green `bb562397`).

Every copy of `TripleIndexes` shares one interner of transaction ids: a class box that appended each new id to an array
and a dictionary, with no lock and no uniqueness check. Copies are written on more than one thread: the store's own
indexes on the store actor, and a copy prepared elsewhere, such as a refused claimed write's component hydrated between
the operation gate's turns while the app keeps writing. Two such writes appended to the same array and dictionary at
once, a data race that corrupts the heap. The concurrency audit found it (#1074, item A15).

Copy on write would copy every interned id into each prepared write, a cost that grows with everything the store ever
wrote. Interning is append-only and an index never changes, so the copies keep sharing the box, and an
`OSAllocatedUnfairLock` now orders its reads and writes. The box is `Sendable` without `@unchecked`.

## Measured

- **The race** (`TripleIndexesInternerRaceTests`: four copies of one `TripleIndexes` each write 20,000 triples with new
  transaction ids on four threads at once, then read back their own newest ids), Mac mini M4, Xcode 27 beta, debug: on
  `c8277988` the test process died with a segmentation fault within a second, and under Thread Sanitizer with
  `ThreadSanitizer: SEGV on unknown address 0x10` (a read from the zero page) before it could report; on `bb562397` it
  passes in 0.35 s, and 3 of 3 under Thread Sanitizer with no warning.

- **Its cost** (#1072's real-size budgets, fixture version 3, release): no measurable change. At the phone's size a
  transcript-line write retired 40.7 million instructions (40.6-47.7 million in the runs before the lock) and a 128-line
  page refresh 373 million (370-373 million before); `RealSizeBudgetTests` passes.

## What stays the same

No schema, migration or public API change. Every copy resolves the same ids at the same indices as before.
