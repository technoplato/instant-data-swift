## What changed

1. **A refused re-send whose values the server's own results show resolves as accepted (#441).** Instant's server
   applies every transact it receives, without deduplicating a re-sent client-event-id (`session.clj`).
   - Library-78 already resolved such a refusal as accepted when later accepted writes of this device covered every
     slot it set. Nothing later wrote the gaps, so 040's refusal stood.
   - Now, for a re-send only, a slot also counts as covered when a live-query result the server sent since the write
     was created shows the write's value. For an identity slot, the result only has to show the entity.
   - Stored results hold only the server's facts, stamped when they are received. The write resolves as
     `supersededByAcceptedWrite`, with the newer of the processed watermark and the covering writes' transaction id,
     so it leaves the outbox at the next server apply.
   - A first offer's refusal is the server's verdict on the write itself, and still fails.
2. **A re-send refused before the connection's query answers waits for them (#441).** The re-sent backlog often
   arrives before the add-query answers.
   - If the connection still owes the first answer to a registered query, the refusal is parked. It keeps its claim, is
     not offered again, and is checked again after every `add-query-ok`, `add-query-exists` and `refresh-ok`.
   - It stands once the server has answered every query without a result that shows the values, or after 30 s.
   - A refusal that stands after waiting logs `outbox.mutation.refused-write` with the write's values, as an immediate
     one does.
3. **The superseded rule as read-only API (#445).** `InstantSwiftDataClient.supersession(ofFailedMutation:)` and
   `failedMutationSupersessions()` say whether a retained failed mutation is superseded, slot by slot.
   - Each slot names what covers it: a later write of this device that the server accepted (with its transaction id),
     or a server result (with when it arrived).
   - A slot nothing covers names a later write still in flight, or the values the server's newest result shows.
   - Retractions, deletions and lookup steps are never covered.
   - A superseded failed mutation can be discarded with `discardFailedMutation(id:)` without losing anything the server
     does not hold. The work runs on the persistence actor, never on the main actor.

## For users of the library

- **API:** additive. New: `InstantMutationSupersession`, `InstantSlotCoverage`, and the two client methods above. No
  existing signature changes.
- **Behavior:**
  - A refused re-send that the server's results vouch for becomes `.confirmed` with `.supersededByAcceptedWrite`
    instead of `.failed`.
  - A refused re-send can stay `.pending` for up to 30 s while its connection's queries are answered.
  - New diagnostics events: `outbox.mutation.refusal-awaiting-server-result`, and a `serverResultSlotCount` field on
    `outbox.mutation.refusal-superseded`.
- **Storage:** no schema or data migration.
- **Dependencies:** unchanged from 1.9.3.

## Known open items

- The guard resolves a refused re-send only when every slot it sets is in a live-query result the device holds, or
  covered by a later accepted write. If no subscribed query includes a slot (a query that selects fields, or none for
  that entity), the refusal stands, as before.
- The supersession API names a later accepted write only while that write is still in the outbox, until the next
  server apply prunes it. After that, the slot reports what the server's newest result shows: `.serverResult` when
  that is the failed write's value, otherwise `.notCovered` with the newer value.
- Scribe's side of #441, no `updatedAtMs` on capture-time writes, is on the live-stamp branch; with it, a re-sent gaps
  write passes the rule. The final segment's summary and media writes can still meet the same refusal; this guard
  covers them when the server's results show their values.
- Not verified on Michael's devices; Scribe's next build with 1.9.4 is that check.
- The release gate (`validation/run-performance-gate.sh live`) did not run (maintainer authorization quoted above).
- Carried from 1.9.3, as listed in its release document.

## Correctness contract

- Local writes complete after local materialization and durable outbox persistence, never after an implicit cloud wait.
- Offline writes survive relaunch, drain in order, and preserve newer optimistic state during server refresh.
- Rejection is isolated per mutation, query, stream, and media item. Removing a refused write leaves the server's
  values, as upstream does.
- Rapid open-segment rewrites remain monotonic through finalization.
- Swift→TypeScript and TypeScript→Swift lanes must report zero lost, duplicate, reordered, or finalized-regression
  updates.
- Linked and infinite-query fixtures must preserve bounded result cardinality and deterministic result counts.
- Entity delivery and progressive audio/media transfer remain independent.
