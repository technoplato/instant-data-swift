# Instant Swift Data 1.9.75

Status: published under the maintainer's standing authorization for fixes, typed on 2026-10-15: "Fix things when
they're broken. Don't ask me permission." Tagged from `main` (`fe1e8fdd`, its ledger `9258b04a` and this record): every
source change on `main` since `v1.9.74` is now marked ready for a build. It carries 1.9.74.

## Before you upgrade

No public API change, no storage change. A prune batch that holds the server-apply and operation gates 1 s or more
logs one notice, `live-query-results.prune-batch-slow` (category `query`); an app that forwards the library's notices
sends one line for each such batch.

## Release focus

**A prune batch names and times each phase it holds its gates for** (#1129; red `d7f704c1`, green `5a8da3a8`; red
`8b6898ad`, green `fe1e8fdd`).

- On 2026-11-04 a Mac's cadence prune held the server-apply gate 4.5-13.1 s per batch (5,164, 6,205, 4,535 and 5,278
  ms at 21:45; one 13,084 ms hold at 23:40), with every live refresh waiting behind it, and a phone's held a
  recording's first write 1.25 s, while a batch still releases at most 1,000 facts. On 2026-11-05, on the consuming
  app's build 270 (1.9.73, after 1.9.72's unload in place), an iPhone's batch held the operation gate 10,888 ms about
  50 s after a launch, and an interactive one-shot read waited 34,681 ms behind it. Every report named only the
  prune, never the part of it that held the gates.
- Each batch now names its phase in both gates' holder phase (find released row, active keys, choose, residency,
  apply, retract, release memory, unload), so a stall or wait report behind it says which part held the gates, and
  times each phase. "release memory" is the step 1.9.72 added after an unloading batch's apply (#1500): the unloaded
  entities' ownership and outbox rows read, then the ones no loaded result owns released from the hot store.
- A batch that held them `liveQueryResultPruneSlowBatchMilliseconds` (1,000) or more logs one notice with each phase's
  milliseconds, the slowest phase, and the batch's counts: results removed and unloaded, facts removed, orphaned facts
  dropped, facts remaining, and whether a released row is left.
- What a batch chooses, unloads or removes is unchanged. The bootstrap prune passes no timer.
