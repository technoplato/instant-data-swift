## Release focus

A local write and the outbox drain take a third less time. On the cross-SDK runtime benchmark, Swift takes 4.6 times
the TypeScript core's time for one write, down from 7.4 in v1.8.0, and 4.7 times for the reconnect drain, down from
7.4. Relaunch improved little: 6.5 times, down from 6.9.

Michael, verbatim (2026-10-01): "fix this please so it works efficiently as as well as the typescript core library".

This release is library-79's branch `agent/claude-opus-5.5/library-79-hops`: the hop cuts (`158a4515`) and the
shared formatter (`55a15392`) on v1.9.0's code, merged with v1.9.0 as `262378b2`, then merged into main. ADR 0018
(`docs/adr/0018-one-actor-turn-per-step.md`) records the design, the hop map, and the measurements.

## What changed

1. **Each step's persistence work runs in one actor turn (#403).** `SQLitePersistenceStore.run(_:)` runs several of
   its synchronous methods in one turn: one hop, with nothing interleaved (Point-Free's `run`, ep362 at 12:16).
   - transact reads its state, shares, same-id and alias checks, creation cursor, and supersession tail in one turn,
     then saves and reads the status it changed in a second.
   - The connection status reads its six inputs in one turn everywhere, and skips the live session's open flag when
     no live transport exists.
   - The server-apply gate's held flag is read without a hop.
   - Relaunch, the query, `pendingMutations()`, and the explicit flush batch the persistence calls that sat next to
     each other.

   Each method keeps its own SQLite transaction and revision check, so the same statements run in the same order. One
   transact makes 7 actor calls instead of 19, a relaunch 11 instead of 16, and a reconnect drain 25 instead of 50.
   Tests pin each count.
2. **One shared ISO 8601 formatter for transport dates (#403).** Lowering a mutation for the wire created an
   `ISO8601DateFormatter` for every date value, and a transact lowers its mutation more than once. That setup was
   about 30% of transact's profile and 34% of the explicit flush's. One formatter with the same options now formats
   every value. The strings are byte-identical, pinned against `@instantdb/core` 1.0.49's own wire encoding of 79
   dates, a fresh formatter over 2,005 dates, and 3,200 concurrent calls.

## For users of the library

- **API:** no public change. The new entry points are `package`-level.
- **Behavior:** the same SQLite statements run in the same order. Two orderings changed:
  - In a transact, the outbox reads now run before the shared-root authorization check, in the same turn. They are
    reads; their only possible side effect is quarantining a row that cannot be decoded, which the next read would do
    anyway.
  - The startup diagnostic `query-cache.pruned-at-bootstrap` is recorded after the compact state loads.
- **Storage:** no schema or data migration.
- **Dependencies:** unchanged from 1.9.0.

| --- | --- | --- | --- |

The hop cuts are structural, not a speedup: an uncontended actor round trip costs about 0.1 µs here, so twelve fewer
hops save about a microsecond per write. The time is CPU work. The formatter was the largest piece; the profile of
this release names what is left: SQLite's WAL writes for the durable outbox, statement preparation (33% of
bootstrap's samples), JSON fingerprints, and bootstrap's 25 migration checks.

Part of the remaining ratio is durability the library keeps on purpose. The TypeScript benchmark persists to
`fake-indexeddb` in memory, and `Reactor.js` saves pending mutations up to 100 ms after `pushOps` returns, while Swift's
`await transact` returns after a committed SQLite row.

| Relaunch | 16 | 11 |

## Correctness contract

- Local writes complete after local materialization and durable outbox persistence, never after an implicit cloud wait.
- Offline writes survive relaunch, drain in order, and preserve newer optimistic state during server refresh.
- Rejection is isolated per mutation, query, stream, and media item. Removing a refused write leaves the server's
  values, as upstream does.
- Rapid open-segment rewrites remain monotonic through finalization.
- Swift→TypeScript and TypeScript→Swift lanes must report zero lost, duplicate, reordered, or finalized-regression
  updates.
- Linked and infinite-query fixtures must preserve bounded result cardinality and deterministic result counts.
- Entity delivery and progressive audio/media transfer remain independent.

- Every correctness and performance comparison to emit zero failures.
