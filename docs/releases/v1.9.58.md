## Release focus

**An observer keeps the ids its result shows** (#1495; red `3cce5ca1`, green `9051d75e`, exercise `ff8fb803`, merge
`e6e71913`). The set of every entity id an observer's result shows is collected once per result and kept on the
observer while it holds that result, as its own or as the one it was last handed. The refresh decision, the splice
and the absent-entity check read it instead of walking the whole result again on each publication. The same observers
refresh and the same values are handed over.

Measured on a Mac mini (M4, release), the fan-out exercise (48 observers, three 50-row recordings lists with five
includes, 8 live transcript pages, 37 small queries; 2,000 writes in the app's shape):

| Measure | Before (`3cce5ca1`) | After (`9051d75e`) |
| --- | --- | --- |
| id sets collected per 2,000 writes | 6,350 | queued (`perf-read-1495-fanout-after`) |
| a final line's publication, p50 | 18.4 ms | queued |
| share of a publication spent on id sets (sampled) | about 1% | queued |

The pin `anUnchangedObserverCollectsNoEntityIDSet` goes from 3 and 3 sets to 0 and 0. Re-materialization is 92% of a
publication's time; that lever is #1513, not in this release.

Also on `main` since 1.9.57 and outside the library's products: `PublishFanOutExercises`
(`INSTANT_PUBLISH_FANOUT=1`), the exercise above.
