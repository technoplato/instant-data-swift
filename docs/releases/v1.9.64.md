# Instant Swift Data 1.9.64

Status: published under the maintainer's standing authorization for fixes, typed on 2026-10-15: "Fix things when
they're broken. Don't ask me permission." Tagged from `main` (`b2156d7d` plus this release record): every source change
on `main` since `v1.9.63` is now marked ready for a build. It carries 1.9.63.

## Before you upgrade

No public API change. **One storage change, forward only:** a live write's outbox body is stored compressed. A body
1.9.63 or older stored as text reads as before and is rewritten compressed at its next change; `lifecycle_bytes` is
added without rewriting a row. An older version cannot read a compressed body: do not open a store this version wrote
with an older one while writes are pending, or they are quarantined.

## Release focus

**A live write's outbox body is stored compressed in its leaf, its lifecycle derived** (#1510, #1463; red `ef3862c9`,
green `a6debcdf`, fixes `4bb6ddc0` `9b2b25ce`; merge `cb95ef5d`).

- `instant_outbox_bodies.json` holds the body's JSON as raw deflate (Apple's Compression framework) behind a 5-byte
  header; `lifecycle_json` is NULL and readers derive the lifecycle. A WITHOUT ROWID cell keeps at most 1,002 bytes on
  its leaf: uncompressed, a phone's live write took two to four overflow pages, allocated at the save and freed at the
  echo; compressed, 6 of 8 live cells fit.
- Every budget still counts JSON bytes.

**The write recorder, with its cost fixed** (#1510; recorder merge `d3b08d41`; fix red `7495e6aa`, green `f63de075`,
switches `527b6b8d`; merge `9922c9bd`).

- `InstantSQLiteWriteRecorder` counts the store's log pages by table and index, by write statement and by store call,
  so an app's energy ledger can name where a save's pages go. A statement shape's written b-trees are explained once a
  process for each schema, not once a store. Environment switches turn it, or its parts, off.

Measured:

| Measure | Before | After |
| --- | --- | --- |
| a save's log frames a write (StorageIOExercises.aLiveWritesStepsByBTree, 48 writes, one job) | 16.3 (65.5 KB) | 13.2 (53.1 KB) |
| an echo's log frames a write (same job) | 18.9 (76.1 KB) | 17.5 (70.6 KB) |
| a store's first write, recorder on (Mac mini, release, 3 rounds) | 0.645 ms | 0.459 ms |
| relaunch (same) | 1.41 ms | 1.26 ms |
| reconnect drain (same) | 0.90 ms | 0.81 ms |

The cost, said plainly: with the recorder on, a store's first write is 0.459 ms against 0.384 ms with it off. Before
its fix the recorder added 0.26 ms to a tight-loop transact (0.449 -> 0.712 ms p50, #1491's bisect); the compressed
body's own cost A/B on the Mac mini was within noise.
