Status: published under the maintainer's standing authorization for fixes, typed on 2026-10-15: "Fix things when
they're broken. Don't ask me permission." and the instruction of 2026-10-23 to land every green step on main. The
release is cut at main after green `48e3b294` (red `92d33847`); main's other commits since 1.9.43 are documents and a

## Before you upgrade

Nothing new: 1.9.44 adds no migration and changes no stored format. 1.9.41's warning stands: a store 1.9.40 or later
opened cannot be used by an older build, so an app that keeps its store across installs must delete its data before an
older build is installed over it.

## Release focus

**The live socket and storage requests stay off cellular while Wi-Fi works** (#1237, #1231). On one device the
Wi-Fi's internet link failed for about 45 s while the Wi-Fi itself stayed associated and stayed the path's primary
interface. Wi-Fi Assist opened the live socket's reconnect over cellular, and the storage connection (HTTP/3) migrated
to cellular "because PTO count is > 3" and marked Wi-Fi unreachable for good; both stayed there for the remaining 57
minutes of the session: 368 MB up over cellular, 341 mWh of the battery by the device's own accounting, while other
connections used Wi-Fi again within four minutes. The path never changed, so nothing that watched it could move them
back, and the system's "Better alternate path available" reached no handler (URLSession installs none).

1. **The path keeps its cost** (`InstantNetworkPath.system`): whether it is satisfied, expensive (cellular or a personal
   hotspot) or constrained (Low Data Mode), its interface, and a generation that changes with them. Each change logs
   `network.path-changed` at notice; before, no line said when the path changed.
2. **New connections ask the system for a route that is not expensive while the path has one** (Apple, "Reducing
   networking and Bluetooth power usage": "To prevent network tasks from using an expensive network, set
   allowsExpensiveNetworkAccess to false."). The live socket's request carries
   `InstantLiveSessionRequest.allowsExpensiveNetworkAccess` (default `true`; the runtime sets `false` while the path
   has Wi-Fi or a wired link), so Wi-Fi Assist cannot open it over cellular. An attempt that fails to open is followed
   by one on any network, and attempts stop asking until a backoff ends (one minute, doubling to 32; Apple's exponential
   backoff "to prevent energy-draining retry loops"): a device whose only working route is cellular still connects.
3. **A socket that may be on an expensive network moves back** (upstream `Reactor.js`: its `NetworkListener` calls
   `_startSocket()` on every change to online, and `_startSocket` closes an open previous transport). A socket that
   opened allowing expensive networks is replaced, through the reconnect controller, on the first evidence that a route
   that is not expensive works: the path changes to one, a storage request that asked for one goes through after a
   failure, or a probe answers after the backoff (one TCP connection to the socket's host that prohibits expensive
   paths, ready within five seconds, then cancelled). At most one move a minute; `network.path-reconnect` at notice
   names the reason, the path at open and the path now. No error is recorded: the outbox, queries, rooms and streams
   resume as on any reconnect.
4. **Storage requests prefer a route that is not expensive** (`InstantStorageHTTPClient.live`): while the path has one
   and the caller's request allows expensive networks, a request first asks for one; URLSession keeps the connections of
   such requests apart from those of requests that allow expensive networks (measured on a Mac, loopback), so it never
   rides a connection Wi-Fi Assist moved to cellular. When that attempt fails on the network (the system finds no such
   route, or it times out, drops or reaches no host), the caller's own request goes at once; a caller's refusal of
   expensive networks is never widened. A small body's first attempt waits at most five seconds for data; a large one
   keeps the caller's timeout, so a slow answer never sends it twice.
5. **Each storage response says which route its transfer used**: `InstantStorageHTTPResponse.route` and
   `InstantStorageHTTPFileResponse.route` (`InstantNetworkRoute`: cellular, expensive, constrained), from the task's own
   `URLSessionTaskMetrics`.
6. **`InstantNetworkRouteMeter.snapshot()`**: the open socket's access (`not-expensive`, `any-network`, or none open),
   its moves, and the attempts and probes on a route that is not expensive that failed, for an app's energy ledger.

## What stays the same

Custom transports and storage clients: `allowsExpensiveNetworkAccess` defaults to `true` and a custom transport may
ignore it; `route` defaults to nil. watchOS and the simulators keep `InstantNetworkPath.alwaysSatisfied`: no preference,
no probe, no move. A socket that opened on a route that is not expensive is never moved: the system keeps it off
cellular. The reconnect controller's backoff (upstream's `_reconnectTimeoutMs`) is unchanged.
