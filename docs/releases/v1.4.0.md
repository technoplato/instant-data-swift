## 1.4.0 — Parity inventories make API convergence checkable

Scribe and every Instant Swift client claim to match InstantDB TypeScript and
Point-Free SQLiteData ergonomics. Until this release that claim lived in tribal
knowledge: nothing listed upstream's full test surface, and nothing failed when
a Swift test was renamed or an upstream case went unclaimed.

### What was wrong

"We have parity" was an assertion, not a measurement. The Instant TypeScript
registry stored paraphrased test names and a few stale Swift identifiers, so
automation could not answer "did upstream add a test we missed?" SQLiteData
had 41 ad-hoc parity rows against 261 real upstream tests, with CloudKit and
SQL-only cases mixed into the same story without an explicit not-applicable
reason.

Separately, several store and CLI expectations still assumed outbox revision
stayed frozen when a server apply only rebased pending local rows, and that
`mutationCount` meant "batch size" rather than outbox size at flush time. Those
expectations already failed on the unpushed 1.3.1 tip; they are corrected here
so a full `swift test` is honest again.

### What changed

- Vendored InstantDB inventory at `e7101761` (225 runtime cases + 1 bench) with
  `InstantUpstreamParityReconciliationTests` enforcing counts, commit pin, and
  bidirectional name resolution.
- Vendored SQLiteData inventory at `0c79d7a` (261 runtime tests) with
  `InstantSQLiteDataParityReconciliationTests` and a complete parity registry
  (518 records total). CloudKit SyncEngine and pure SQL surfaces are
  `notApplicable` with written reasons; portable ergonomics (date roundtrip,
  assertQuery-style materialization dumps, empty batches, selection edges) are
  adapted and tested.
- Upstream `instaql.bench.ts` deep-join is ported as `LocalRead.deepJoin.zeneca`
  and measured (~4.9× slower than TypeScript on this machine — performance work,
  not a missing port).
- Test expectations updated for outbox rebase revision bumps, flush
  `mutationCount` semantics, and a few reactor/CLI pins that already failed on
  1.3.1.

### How this was verified

- Full package suite: **1351 tests in 115 suites passed** (10 known issues only,
  including pre-existing live-encoding and stale-outbox known issues).
- Reconciliation suites pin both upstream checkouts and fail if a test is added
  upstream without a record, or if a Swift test name in a record disappears.

### Upgrading

Pin `exact: "1.4.0"` (or the matching tag) for
`https://github.com/technoplato/instant-data-swift.git`. No schema migration.
No Instant server deploy required. Consumers that pin parity coverage counts in
their own harnesses must adopt the new totals (518 records / 282 adapted / 206
not-applicable).
