## Release focus

An upload keeps no copy of its file, and the copies kept before can go once storage holds them (#959). On one device
the file store held 3,754 such copies: 25.9 GB of logical size, of which 10.8 GB were real blocks (the rest were APFS
clones of files the app still kept).

## 1. An upload through storage keeps no copy

`uploadFile(from:name:contentType:)` with a storage transport used to PUT the file and then copy it into
`files/<app>/<file>/` beside the SQLite store, and keep that copy for good. Upstream's `StorageAPI.uploadFile` keeps
nothing: storage holds the file once the upload returns. Now the device keeps the file's record (id, name, content type,
size) and no copy of its bytes:

- The returned `InstantStoredFile` has `localPath == ""` and `isDownloaded == false`. The caller keeps its own file.
- `storedFileContents(id:)` and `downloadStoredFile(id:to:)` of a record without a copy download it by the name it was
  stored under, with no list of every file.
- `storageSnapshot()` counts held copies only.
- A client without storage keeps its copy, as before: there it is the only one.

`copyItem` on APFS made a clone, so a copy of a file the caller still kept cost no blocks until either changed. A file
the caller deletes after its upload (a chunk written only to be sent) left its clone as the only holder of its blocks.

## 2. `evictStoredFiles(ids:)`: copies storage holds can go

For copies kept before this release, and for `storedFileContents(id:)`'s cache:

```swift
let held = try await db.localReader().storedFiles().filter(\.isDownloaded)
let evictions = try await db.evictStoredFiles(ids: held.map(\.id))
```

A copy goes only when storage's own record of the file (`$files`, read by id over the open connection, 100 ids a query)
has the copy's size. Its record stays, not downloaded, so a read fetches it again by its stored name. Each
`InstantStoredFileEviction` says what happened: `.evicted(freedByteCount:)` with the bytes the volume got back (APFS
`ATTR_CMNEXT_PRIVATESIZE`: next to nothing for a clone of a file the app keeps), or `.kept` with the reason
(`.notHeld`, `.noStorage`, `.notOnServer`, `.sizeDiffers(serverByteCount:)`). With the connection closed it throws and
every copy stays. Success waits for storage's records over the connection, unlike `transact`.

The local reader's `storedFiles()` now reads this device's records alone, with or without a copy.

## Upgrade notes

- Code that read `localPath` of an uploaded file must read its own source file instead, or download the record.
- `evictStoredFiles` is new; nothing calls it unless the app does.
