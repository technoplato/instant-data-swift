# Instant Swift Data 1.9.27

Status: published under the maintainer's standing authorization for fixes, typed on 2026-10-15: "Fix things when
they're broken. Don't ask me permission." and the instruction of 2026-10-23 to land every green step on main. The
checks that ran are below; the last code commit is `4fb1f457`. It carries 1.9.26 (#1024, and the #932 and #1012
commits its document names) and 1.9.25 (#932, #590).

## Release focus

A live write costs about 15% less CPU (#1007): it no longer prepares its SQL again every time, reusing a prepared
statement no longer costs a dozen hashes of its SQL, and a fact's stored text is written without `JSONEncoder`.

1. **The statement cache keeps 256 statements instead of 64** (red `ef64c39b`, green `baa1796a`). A live write's save,
   delivery claim, acknowledgement and the apply of the server's answer run about 150 distinct statements. With 64
   kept and the least recently used one evicted, each statement was evicted just before its next use, so every write
   parsed and planned all of them again. A Time Profiler trace of the write harness put 7.0% of all CPU in the cache's
   check-out, nearly all of it SQLite parsing and planning, and 2.7% in its check-in.
2. **A kept statement's reuse hashes its SQL once** (red `5074b761`, green `0130581a`). The cache took a statement out
   of its idle map at check-out and put it back at check-in, hashing the SQL five times a use, and each removal from a
   Swift dictionary re-hashed the neighbors it shifted; SQL keys are hundreds of characters long. Each SQL text now has
   one entry that stays in place while its statement is out, and the check-in reaches the entry through the statement.

3. **A fact's stored text is written without `JSONEncoder`** (red `90925360`, green `4fb1f457`). Every fact a write
   stores encoded its value (`value_json`, part of the facts' key and of their lookups) and then the whole fact (`json`),
   the value a second time inside it. In the trace, `JSONEncoder` under the fact insert was 5.0% of all CPU, nine
   tenths of it containers, type casts, metadata lookups and allocations. `InstantStoredJSON` writes the text of null,
   string, number, boolean, ref and date values and of a fact exactly as `JSONEncoder` with `.sortedKeys` writes it,
   the value once; a JSON value or a lookup ref, whose object keys `JSONEncoder` sorts its own way, and a number that
   is not finite are still `JSONEncoder`'s.

## What stays the same

Every statement runs as before. A kept statement is reset with its bindings cleared, so it holds no read snapshot and
no bound value; one idle statement is kept per SQL text, a nested use of the same SQL gets its own statement, DDL and
statements with more than 32 parameters are not kept, the least recently used is finalized past the capacity, and a
statement out when its connection closes is finalized when it comes back. The cost is memory: the measured write cycle
keeps 150 statements in 954 KB of SQLite's statement memory, where 64 held 415 KB; a full cache of 256 would hold about
1.6 MB on the writer connection. Every stored text is the text `JSONEncoder` wrote before, byte for byte, so stored
facts written by an earlier version are found and replaced as before.

## Not changed here

  its optimistic effect (the fingerprint 4.6% of the harness's CPU), and a JSON value is still `JSONEncoder`'s.
