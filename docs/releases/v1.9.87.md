## Before you upgrade

`InstantAudioSegmenter` gains `cancel()`, an `onEnd` parameter (defaulted) and the `Ending` enum; nothing is removed.
What a segmenter encodes does not change: the same initialization segment and media segments for the same PCM.
Behaviour that changes, each a case that used to raise an Objective-C exception or leave a writer running:

- A segmenter released while its writer still writes cancels the writer (`Ending.cancelledAtRelease`).
- A second `finish()` returns the first one's outcome instead of finishing a completed file.
- `append(_:)` after the end (a finish, a cancel or a failure) throws, including an append that was waiting for the
  input when a finish or cancel ran (the actor is reentrant at that wait).
- `finish()` on a writer that already failed throws without asking AVAssetWriter to finish.

## Release focus

**Every AVAssetWriter the segmenter starts ends exactly once, inside the actor, before it is released** (#2529).

- Why: AVAssetWriter crashed on its own queue (`com.apple.coremedia.assetwriter`, inside a CoreMedia deferred
  notification of its export state machine, reading a freed CFArray or CFDictionary; once a double free on the format
  writer's thread) in three test processes of a consuming app, each holding two or three writers, some dropped while
  still writing, and once in a command-line encoder holding one. The segmenter had no way to cancel and no deinit, so
  an owner that let it go mid-write deallocated a writing AVAssetWriter.
- Now: `WriterLifetime` owns the writer and cancels it when released unfinished; `finish()`, `cancel()` and a failed
  append each end it once and say how through `onEnd`.
