## 1.5.0 — Empty live results no longer blank pending optimistic children

Scribe, a continuous voice recorder, opened a finished recording on iPad:
playback scrubbed audio fine, but the detail surface was white — no
transcript, no screenshots, no clipboard. The list still claimed “3 words.”

Tailnet diagnostics showed the smoking gun in one line:
`recording.query.detail.local-snapshot` with `attachmentCount=1` and
`transcriptionCount=0`, `segmentCount=0`, `wordCount=0`. Moments earlier the
list had flickered `transcriptionCount` from `1` to `0` right after a local
create. Instant admin queries returned zero recording or transcription rows;
the outbox was still full of pending mutations.

The library had done what ADR 0008 asked for an authoritative empty live
result: retract every triple the previous query result owned. Upstream Instant
can do that safely because it keeps a separate server store and re-applies the
optimistic overlay on every read. Swift materializes **one** store. Empty
replacement retractions therefore erased pending optimistic children while the
outbox still believed they were durable. Join-shaped detail (recording root +
linked transcriptions) is the place that failure becomes a blank screen.

**1.5.0** refuses to retract triples for entities still covered by a non-failed
pending optimistic mutation. Pure server rows with no pending coverage still
disappear on empty replacement. The Linked Infinite recipe now opens a detail
surface for each row and documents the contract; two focused tests lock the
behaviour:

- `emptyLiveQueryReplacementPreservesPendingOptimisticChildRows`
- `emptyLiveQueryReplacementPreservesOptimisticTranscriptionJoin`

Pin `exact: "1.5.0"` (or the matching tag). ADR:
`docs/adr/0013-protect-pending-optimistic-from-empty-live-query-retractions.md`.
