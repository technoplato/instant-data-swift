# Instant Swift Data 1.9.24

Status: published under the maintainer's standing authorization for fixes, typed on 2026-10-15: "Fix things when
they're broken. Don't ask me permission." and the instruction of 2026-10-23 to land every green step on main. The
checks that ran are below; the last code commit is `6b1dd7b4`.

## Release focus

A write's cycle writes about 9% fewer pages to disk: the outbox drops an index no statement used, and an
acknowledgement no longer rewrites three indexes whose keys it does not change (#1007).

1. **The outbox drops `instant_outbox_delivery_window_idx`** (red `5fc3a128`, green `6b1dd7b4`). Every insert,
   claim, acknowledgement and delete of an outbox row wrote a page of it, and no statement's query plan used it: the
   statements that filter on the claim state alone use `instant_outbox_delivery_deadline_idx`, which leads with the
   same column, and the ones that name the delivery state hold it inside an `OR`. Migration
   `0028_drop_unused_outbox_delivery_window_index` drops it.
2. **An acknowledgement sets the overlay flag only when it changes** (same commits). Its `UPDATE` set
   `optimistic_overlay_active` to the value the row nearly always held already, and SQLite rewrites a row's entry in
   every index holding a column an `UPDATE` sets, changed or not: three indexes (effect normalization, global effect
   order, synchronization blocker) on every acknowledgement. The flag is now set in its own `UPDATE`, in the same
   transaction, only when the row holds the other value.

## What stays the same

No query plan changes: no plan used the dropped index. An audit ran `EXPLAIN QUERY PLAN` on every outbox statement
against the final schema rebuilt in an in-memory SQLite (macOS SQLite 3.51.0; the store never runs `ANALYZE`, so
the planner uses the same default estimates on a phone), with the index and without it, and every plan stayed the
same. An acknowledgement leaves the row as it did, in one transaction. Delivery, claims and acknowledgements run in the
same order and at the same moments, so a write reaches the server and the server's changes reach observers as before.

## Not changed here

- A write resolved as accepted because later accepted writes cover it (a re-sent or refused write only) still sets the
  overlay flag in its main `UPDATE`.
- `instant_outbox_delivery_metadata_idx` stays. Dropping it saves three pages a write, but the reduced server apply's
  metadata check would then read each active row's body, about 2,600 rows during a backlog.
- A one-shot query rewrites its whole cached result on every call, unchanged or not.
