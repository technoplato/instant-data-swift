## Before you upgrade

No migration, no stored format change. New public API: `InstantLiveTransportClient.liveEventStream`,
`.liveWebSocket` and `.liveKind`; `.live` is now the event stream on watchOS and the WebSocket elsewhere.

## Release focus

**On watchOS the live session runs over Server-Sent Events** (#1315). watchOS treats `URLSessionWebSocketTask` as
low-level networking and blocks it unless an audio app is streaming audio or a call is running (Apple TN3135; the
simulator always allows it). On a physical Watch every socket attempt timed out at 5 s and live queries never
answered, so rows written on another device never arrived, and writes queued on the Watch waited for its next audio
session.

The event stream is upstream's `SSEConnection` (`client/packages/core/src/Connection.ts`): a GET of
`/runtime/sse?app_id=` streams the server's messages, `sse-init` first; client messages go as POSTs to the same URL
with the stream's ids and token, batched and in order like upstream's `flushQueue`. Both are plain HTTP, which watchOS
allows every app. The stream's idle bound is 20 s: a quiet stream carries a `:` comment every 15 s (measured on
api.instantdb.com, 2026-10-28).

Measured from a Mac against the hosted server (guest, no writes): `sse-init` 0.24 s, POST `init` 200 at 0.35 s,
`init-ok` on the stream at 0.52 s; the library's own probe test answered `init` and, after a 35 s quiet hold, a query.
